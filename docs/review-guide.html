00 · 무엇을 만드는가

한 문장 요약

사용자가 LLM과 대화하며 얻은 생각·질문·통찰을 자동으로 골라, 기존 Markdown 노트와 비교한 뒤 새 Note 만들기(CREATE) / 기존 Note에 덧붙이기(UPDATE) / 연결 추가(LINK) / 아무것도 안 함(NONE) 중 하나로 지식베이스에 반영하고, 그 변경을 언제든 되돌릴(Undo) 수 있게 하는 로컬 앱이다.

Markdown이 진짜 데이터

notes/*.md가 원본이다. DB가 사라져도 지식은 남는다.

DB는 파생 데이터

검색 색인·임베딩은 언제든 Markdown/PDF에서 다시 만들 수 있다.

AI 변경은 되돌릴 수 있다

자동 반영 대신 매번 묻지 않고, 대신 기록하고 Undo를 제공한다.

01 · 먼저 실행해 보기

코드를 읽기 전에 직접 써 본다

화면을 먼저 써 보면 코드가 "어떤 버튼의 뒤편"인지 연결하기 쉽다. 자세한 설명은 README.md.

  1. 준비물: Python 3.11+와 uv, Node 20+, Docker Desktop, Ollama(qwen3.5:4b-mlx).
  2. 설정과 의존성 
    cp .env.example .env
cd backend && uv sync && cd ..
cd frontend && npm ci && cd ..
docker compose -f docker/docker-compose.yml up -d
  3. 서버 두 개 실행(터미널 2개) 
    cd backend && uv run --env-file ../.env uvicorn app.main:app --host 127.0.0.1 --port 8000
cd frontend && npm run dev
  4. 브라우저에서 http://127.0.0.1:5173 → Workspace 경로에 example-workspace의 복사본 경로를 넣고 "열기". 앱은 실제 파일을 고치므로 복사본을 권한다.
  5. 화면 순서대로 써 보기: Notes(편집·링크) → Sources(PDF 넣고 색인) → Search → Chat(3번 주고받기) → 아래 요약의 바뀐 Note → History(Diff, Undo) → Graph → Base.
  6. 테스트: cd backend && uv run --env-file ../.env pytest -q(DB가 켜져 있어야 DB 테스트가 실행된다), cd frontend && npm run typecheck && npm run build.

용어집

용어뜻
Workspace앱이 읽고 쓰는 로컬 폴더. notes/(내 지식)와 sources/(원본 자료)를 가진다.
Note / SourceNote는 내가 이해하고 생각한 것, Source는 근거가 되는 외부 원본(PDF 등). Source는 앱이 고치지 않는다.
파생 데이터원본에서 언제든 다시 만들 수 있는 것(색인, 임베딩, .palette/derived).
flush예약된 자동 저장을 지금 바로 실행하고 끝날 때까지 기다리기.
RAG검색으로 찾은 근거를 LLM에 함께 보내 답하게 하는 방식.
Provider · LLMClient실제 LLM 서비스와 그 호출 규약(인터페이스). 구현체를 바꿔 끼울 수 있다.
reasoning_effort모델의 생각(thinking) 정도. none이면 생각 없이 바로 답한다(속도).
고아 running"실행 중" 표시만 남고 실제로는 돌지 않는 기록(재시작 등). 다음 요청 때 failed로 정리된다.
dropped_links모델이 낸 링크 중 실제 Note로 해석되지 않아 버린 것.
1-hop현재 Note와 직접 연결된 Note까지만.
관련 문서: README · architecture · implementation-decisions · 작업 내역(명시되지 않은 선택). 코드 지도는 graphify(graphify update, LLM 없이 AST 추출) 결과를 파일 단위로 요약했다.
